# ADR-007: Publish ledger events through the Kafka event bus

- Status: Accepted
- Decided by: Vik
- Date: 2026-08-05
- Affected services: ledger-service, event-bus
- Related project: Project Helix, Project Pulsar

## Context

Downstream consumers (reconciliation, the analytics warehouse loader, and the fraud feature jobs) currently poll the
ledger database every few minutes. Polling puts read load on the primary, the lag is unpredictable, and every new
consumer reinvents its own cursor logic.

We already run Kafka for clickstream and order events, and the platform team has spare capacity on the cluster.

## Decision

The ledger service will publish one `LedgerEntryPosted` event per committed entry to the `ledger-events` topic on the
event bus. The publisher runs inside the ledger service process and writes to Kafka directly after the database write
succeeds. Consumers read from the topic instead of polling the ledger tables.

## Consequences

- Consumers get near real-time ledger data without touching the primary database.
- The write to Postgres and the publish to Kafka are two separate steps. If the process dies between them, an entry
  can be committed without an event. We accept this for now and will add a nightly reconciliation job to catch gaps.
- Consumer offset handling has to be correct on every consumer, or retries will produce duplicates. Each consumer team
  is responsible for idempotent handling.
- Schema for `LedgerEntryPosted` is registered in the schema registry with BACKWARD compatibility.
